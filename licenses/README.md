# Licences, SBOM and third-party notices (REQ-S16-009, REQ-S19-003; P1 increment)

| File                                                                       | Generated by                                  | Contents                                                                                                                                                                                                                                 |
| -------------------------------------------------------------------------- | --------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `sbom.cdx.json`                                                            | `node licenses/generate-sbom.mjs`             | CycloneDX 1.6 SBOM from `pnpm-lock.yaml`: every package with purl, SHA-512 integrity (from the lockfile), licence (from the installed package.json), scope, direct-dependency edges; the container images from `deploy/images.lock.json` |
| `inventory.csv`                                                            | same                                          | One row per package: `name,version,license,scope,direct_dependency_of,integrity`                                                                                                                                                         |
| `THIRD-PARTY-NOTICES.md` (in the image at `/app/licenses/`, not committed) | `node licenses/collect-notices.mjs --out DIR` | Full LICENSE/NOTICE/COPYING/OFL texts of every **shipped** package (scopes `runtime` + `bundled`); packages that ship no licence file are listed explicitly                                                                              |

Scopes: `runtime` means the package is shipped as `node_modules` in the `mth-app` image (reachable from the
production dependencies of api, worker, config, db and shared). `bundled` means it is compiled into the web bundle
(reachable only from `apps/web` production dependencies; also present in the image's store). `development` means
build, lint and test tooling, never shipped.

The image build (`deploy/scripts/assemble-runtime.sh`) fails if the runtime tree contains any package outside the
`runtime`/`bundled` set of `inventory.csv`.

`--check` (run in CI's `images` job) fails when the committed files differ from a fresh generation, meaning the
lockfile changed without regenerating, or when a shipped package has no licence id.
