HOW TO USE THIS PLAYBOOK <!-- B0006 -->


One System, Two Modes <!-- B0007 -->


Use this playbook in two ways: as a full end-to-end transformation methodology, or as a modular toolkit when you only need a specific deliverable (for example, a Target Operating Model, initiative business case, or benefits register). <!-- B0008 -->


<!-- B0009 table -->
| Mode | When to use | How |
|---|---|---|
| End-to-End | New enterprise or business-unit transformation | Run Phases 1-6 sequentially. Do not launch initiatives before the North Star, outcomes and target state are clear. |
| Modular | A transformation is already underway | Enter at the relevant phase, complete the minimum mandatory templates, then reconnect to outcomes and benefits. |


Design principles <!-- B0010 -->


Outcome before activity: define measurable business outcomes before building a project list. <!-- B0011 -->


Current state before solution: diagnose economics, customer, operations, capability and technology before prescribing initiatives. <!-- B0012 -->


Operating model before execution: make decision rights, ownership and cross-functional ways of working explicit. <!-- B0013 -->


Benefits before closure: an initiative is not complete when delivered; it is complete when value is realized and sustained. <!-- B0014 -->


One source of truth: keep the transformation charter, roadmap, initiative portfolio and benefits register linked. <!-- B0015 -->


<!-- B0016 table -->
| Rule of thumb  Every transformation deliverable should answer one of four questions: Why change? What must become different? How will we execute? How will we prove value? |
|---|


Minimum governance roles <!-- B0017 -->


<!-- B0018 table -->
| Role | Accountability |
|---|---|
| Executive Sponsor | Owns enterprise outcome, removes constraints, approves major trade-offs. |
| Transformation Lead | Integrates workstreams, drives cadence, ensures outcome realization. |
| Business Owners | Own target-state capabilities and BAU adoption. |
| Workstream Leads | Deliver initiatives and manage dependencies. |
| Finance / Value Office | Validates baseline, benefit logic, value realization. |
| Transformation Office | Governance, reporting, risks, dependencies, decisions, standards. |


METHODOLOGY <!-- B0019 -->


The 6-Phase Transformation System <!-- B0020 -->


<!-- B0021 table -->
| 1 | DIAGNOSE | Establish fact base | Current state, root causes, value pools |
|---|---|---|---|
| 2 | DEFINE | Set direction | North Star, outcomes, KPIs, guardrails |
| 3 | DESIGN | Create target state | Target Operating Model, capabilities, journeys |
| 4 | MOBILIZE | Build execution portfolio | Initiatives, business cases, roadmap, resourcing |
| 5 | TRANSFORM | Execute & govern | Operating system, workstreams, decisions, adoption |
| 6 | REALIZE | Prove & sustain value | Benefits, BAU handover, continuous improvement |


Stage gates <!-- B0022 -->


<!-- B0023 table -->
| Gate | Decision question | Evidence required |
|---|---|---|
| G1 - Case for Change | Do we agree on the problem/opportunity and value at stake? | Diagnostic, baseline, root causes, value pools. |
| G2 - Direction | Are outcomes specific enough to steer decisions? | North Star, outcome tree, KPI definitions, guardrails. |
| G3 - Target State | Do we know what must be different operationally? | Target Operating Model, capability gaps, future journeys. |
| G4 - Mobilization | Is the portfolio executable and value-backed? | Initiative cards, business cases, roadmap, owners, capacity. |
| G5 - Scale | Are pilots/results sufficient to scale? | Performance evidence, adoption, risk closure, decision log. |
| G6 - Sustain | Is value embedded in BAU? | Benefits evidence, ownership transfer, controls, continuous improvement backlog. |


<!-- B0024 table -->
| PMI/Brightline connection  The playbook uses the people-centered transformation logic and transformation operating-system thinking associated with PMI/Brightline, while adding a more explicit Target Operating Model and management-consulting-style diagnostic/design layer. |

PHASE 2 <!-- B0044 -->


02  DEFINE — North Star & Outcomes <!-- B0045 -->


Objective: translate the case for change into measurable transformation outcomes that can steer portfolio and operating-model choices. <!-- B0046 -->


Outcome hierarchy <!-- B0047 -->


<!-- B0048 table -->
| Level | Definition | Example |
|---|---|---|
| North Star | Concise description of the desired future business state. | “Make roaming effortless, trusted and economically accretive.” |
| Strategic Outcomes | What must improve for the North Star to be true. | Revenue growth, activation, customer experience, partner economics. |
| KPIs | Measures proving outcome movement. | Roaming revenue, attach rate, complaint rate, digital activation. |
| Targets | Time-bound ambition. | +X% revenue by Q4; -Y% complaints. |
| Initiative Contribution | How each initiative moves one or more outcomes. | New pass architecture → attach rate + ARPU. |
