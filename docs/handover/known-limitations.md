# Known limitations

This document lists what this release does not do, what it has not proven, and what Mobily IT must still supply. It is
for Mobily IT and the platform's owners. The Arabic summary is
[known-limitations.ar-summary.md](known-limitations.ar-summary.md). This English text is complete.

Accepting this handover is a decision of Mobily IT, made outside the platform. This package is engineering evidence,
not that acceptance.

Compose is a reproducible install and test configuration, not evidence of high-availability readiness.

Sections 1–3 are generated by `tools/release/known-limitations.mjs` and must not be edited by hand. Regenerate them
with `node tools/release/known-limitations.mjs --protocol-audit <report.json> --write`; `--check` fails when they are
stale. Sections 4–6 are written by hand.

## 4. Carried from DG6 {#dg6-carry-forward}

These residuals of DG6 requirement rows are carried here (p7-plan §1.4). Each is a DG6-approved behaviour or an
unproven clause; none is fixed in this release.

| Source row | Limitation |
| --- | --- |
| REQ-S16-007 | The live Keycloak end-to-end sign-in (`mth-test` realm) has never run in the delivery environment: it needs a container runtime (D-049, D-195 Q5, D-197). It is the delivery orchestrator's container host run (D-243 Q1); until that run is recorded it stays BLOCKED. Cross-realm token rejection is carried by an integration test against a local fake identity provider. |
| REQ-DLV-038 | Within the DG6 evidence set, `e2e/identity/keycloak-login` was not run (BLOCKED, as REQ-S16-007). |
| REQ-S10-002 | (a) Ids or codes of restricted records remain visible in some lists and in the frozen G6 submission snapshot. (b) Several lists filter after pagination, so a page can be short while its cursor is not null. (c) A Finance user who is neither the validator nor a grantee cannot open a sensitive benefit's Finance validation. Sweep limits: 71–75 read operations cannot be filled from demo data and are not swept, and the sweep runs with an empty search index. |
| REQ-S16-030 | There is no cross-site-scripting end-to-end test. The clause rests on unit and integration tests (security-controls matrix: integration-level evidence only). |
| REQ-S17-001 | For readers without transformation access, the connector label shows the connector's id, not its code. No test asserts a succeeded run's non-null row counts on screen. |
| REQ-S17-009 | A failed DNS lookup logs the requested host but no port in the connection log. The instrument is a connection log, not a packet capture. |
| REQ-S20-029 | `getWorkstreamDashboard` was not measured in either load run (the load profile writes no workstream). The load targets are provisional engineering targets, measured on a shared 4 vCPU sandbox, not on production infrastructure. |
| REQ-S20-030 | The export proofs ran on the synthetic load dataset; on a loaded host, simultaneous export starts exceeded the 2 s reading of "immediately", and the idle-host re-measurement met it. `export-proof.mjs` still exits 1 on one assertion in each repetition (register notes). |

## 6. Residuals of the P7 architecture decisions {#adr-residuals}

Each P7 ADR states its residuals in a "Residuals (honest)" section. In short:

| ADR | Residuals |
| --- | --- |
| ADR-0062 | The `.tar.gz` archive is reproducible only for the same Node major and zlib; `demo-data/` bytes differ between seedings; the image build and `docker compose up` from the archive need a Docker daemon (orchestrator's host); no IT npm mirror exists in the delivery environment; the asset scan is pattern-based; the procurement flag is an engineering classification, not a legal or procurement decision; live CI not run. |
| ADR-0063 | The secret and claims scans are pattern-based; database TLS has no product-side code (it depends on the driver honouring the URL); encryption at rest is a hosting function; history scope is `HEAD`'s ancestry only; live CI not run; cross-site-scripting evidence is integration-level; the Arabic summaries are provisional. |
| ADR-0064 | Migration scale is unproven; cross-release imports are out of scope; queued jobs do not travel (stop the source's worker and wait for an empty queue first); the attachment manifest lists evidence object names to ADM_TECH; secrets must be re-bound by IT on the target; every imported user is held until IT confirms the identity. |
| ADR-0065 | Some configuration kinds may be refused as unportable; a draft of a new key needs a draft-from-content service; "behaves identically" is shown by assertions and content hashes, not an exhaustive comparison; review-policy items are refused for the default bundle roles. |
| ADR-0066 | Recovery objectives (RPO, RTO) are not set; only measured drill timings exist; after a restore the backup list shows only the sets known when the restored set was taken; scale unproven; secrets are not backed up; no point-in-time recovery; the S3 path is proven only against a local fake. |
| ADR-0067 | Retention periods are placeholders ("not set (IT to agree)"); archived rows are not restored into live tables; business records cannot be archived; pg-boss keeps its own job retention; run scale unproven. |
| ADR-0068 | The irreversible-migration scanner is heuristic; run times on production volumes are unknown; there is no online (zero-downtime) upgrade. |
| ADR-0069 | Container halves depend on the orchestrator's host; a "clean VM" is approximated by a fresh cluster and a namespace with no network; sub-path serving is not supported; the corporate IdP, object store and mail stay external; "host without registry access" is shown with `--pull never`, not on an air-gapped host; already-sent messages keep the old origin; the DNS-port residual of REQ-S17-009 is carried. |
| ADR-0070 | Indexes, constraints and triggers are reported, not gated; the ERD is checked for wrong names, not completeness; connector contract tests run against local adapters only; the data dictionary is extended, not regenerated. |
| ADR-0071 | The register and About role set is wider than "ADM, AUD, TO" (KDS and TD can read); the `.dockerignore` exception is proven only by a real image build; the later-clause marker is a convention; historic protocol hits stay in the approved records (section 2). |
| ADR-0072 | All Arabic text in this release is provisional; the deployment guide is checked structurally and by the transfer drill, while the corporate IdP, TLS certificates, the orchestration target and production monitoring are described, not exercised; the protocol-audit block reflects the report given at the freeze; Markdown right-to-left display depends on the renderer. |
| ADR-0073 | The seal rehearsal is not the release run; the historical validation may be BLOCKED in a partial rehearsal clone; the separation checks are text heuristics; `demo-data/` is not reproducible; the A26 drill depends on where drill review records are written; the orchestrator needs disk room for two archives; no live CI for the seal tests. |
