## 2. Behaviour per requirement

**REQ-S16-031 / REQ-S21-003 (F-DG7-1011).**

- S3 now reports a secret-named key whose value is a high-entropy lower-case or hex string. The reviewer's shapes are covered: `POSTGRES_PASSWORD: <48 hex>` (compose.override.yaml), `s3_access_key: <32 hex>` (values.yaml) and `OIDC_CLIENT_SECRET="<24 lower-case>"` (deploy.conf). Each gives one S3 hit, `secret-scan: FAIL (1 hit…)` with exit 1, and the value is masked `[S3:xxxx…]`.
- Real i18n keys stay exempt. All 8,562 lower-case key paths of ≥ 16 characters in the en and ar dictionaries pass `isI18nKey` and `isNonSecretValue`, and so does `"password_hint": "auth.password.reset_hint_text"` in the non-match fixture.
- Regression proof: against the pre-fix rule, 4 of the 7 new tests fail (`03-…OLD-scanner.log`, exit 1). With the fix, all 32 tests of the file pass.
- Retained trade-off: exactly 64 hex is still exempt as a checksum (ADR-0063 §1.2). The non-match fixture `token = "<64 hex>"` depends on that. It is now disclosed in SC-13 (see §5 Q1 for the ADR).

**REQ-S19-012 (F-DG7-1012).**

- A set taken under umask 022 is 0700 directories and 0600 files throughout, including `.backup-state/`, `config/`, the dump, the manifest and `--record-out` (T-E10).
- In the split Compose sequence, a copy-out written with a 022 umask is repaired by `--phase finish`. `ownerOnly` is recorded as PASS in the manifest `checks` (T-E11).
- A group- or world-writable root (the host `/tmp` case) is refused with exit 2, and nothing is written (T-E12).
- Compose no longer falls back to `/tmp`, and Docker is told not to create a missing host path (static test).
- The handover guide states the permissions the root needs and how to create it.
- Regression proof: against the pre-fix `backup.sh`, T-E10, T-E11 and both T-E12 fail (`05-…OLD-backup-sh.log`, 9 pass / 4 fail, exit 1). With the fix, all 13 pass.

## 4. Known gaps

1. **The Compose half is unverified.** The `create_host_path: false` mount, the refusal of an unset `MTH_BACKUP_ROOT`, the root `backup` service writing 0700/0600, and step 2 with `--user 0:0` were not run, because there is no Docker daemon. They run on the orchestrator's host (D-243 Q1), and backup-restore.md §10 says so. The scripts' behaviour is proven on a disposable PostgreSQL (T-E10 to T-E12). This local evidence is not proof of high-availability production readiness.
2. **Step 2 of §3.2 now runs the app image as root (`--user 0:0`).** It is a pre-existing defect I fixed along the way. Before this change the `backup` service (root) created the set as root 0755, so the app image's user (uid 10001, `deploy/docker/Dockerfile` l.95) could not write `evidence/attachments.json` either. Running that one command as root is the least invasive fix. The alternative is running the `backup` service as `10001:10001` with a uid-10001-owned root, but that depends on the postgres:18 tools running without a passwd entry, which I could not test without Docker. The orchestrator's Compose run should confirm step 2.
3. **The 64-hex checksum exemption stays.** `openssl rand -hex 32` under a secret-named key is not reported (disclosed in SC-13). Narrowing it, for example by exempting 64 hex only under hash-named keys, changes ADR-0063 §1.2 and the T-G1 non-match fixture. That is the solution-architect's decision.
4. **The Arabic bullet** added to the backup-restore summary is provisional (D-243 Q7).
