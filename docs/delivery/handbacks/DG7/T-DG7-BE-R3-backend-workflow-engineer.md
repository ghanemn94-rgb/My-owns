## 2. Behaviour per requirement

### REQ-S19-014 (M0362 "reconciliation") and REQ-S19-017 (B.8 "records, jobs and approvals intact after a full restart")

**A3.2 automation chain.** This is implemented exactly as written:

- E is step 1.
- An outbox row is explained only when it is added (not in the package) and an E* event matches it on `record_type`/`record_id`/`organization_id`, with `occurred_at = created_at` compared as `timestamptz` in SQL.
- An execution is chain-explained only when all of these hold:
  - its trigger is `trigger_kind = 'event'`;
  - exactly one explained outbox row has `idempotency_key = trigger_key` and `event_type = trigger_code`;
  - its recorded user (`initiating_user_id`, else `trigger_payload ->> initiating_user_field`), if any, is in `actors`;
  - its own service events after B have `request_id`s that are all `^job:.+$`. **I also require at least one such event.**
- The job's service events (`on_behalf_of_user_id` NULL or in `actors`) then join E*. This repeats until nothing changes.
- `explainAudited` uses E* for every audited table. Automation rows count under `audit_explained`, and no new basis is written for them.

**A3.3 counter basis.**

- `RECHECK_COUNTER_TABLES.record_code_counter` maps every prefix whose coded table I verified at every call site of the counter (`grep -rn record_code_counter`). The full list, with the call sites, is in the constant's doc comment.
- **`B` is listed as unmapped.** Benefit codes read `B01` with no hyphen (`benefits/register.ts`, 0037 CHECK `^B[0-9]{2,6}$`), and the A3.3 pattern `^<p>-([0-9]{2,6})$` cannot match them.
- A counter row is explained only when `new > old` and the numbers parsed from the explained **added** rows of its scope equal exactly `{old+1…new}`. The prefix is matched exactly.
- These cases are unexplained:
  - a missing counter row;
  - an unmapped prefix that changed;
  - an explained coded row whose counter did not move (item 5).
- Up to 20 lines `    counter <key>: moved <old> -> <new>, <n> new coded rows (<numbers|none>)` follow the per-table line `(counter)`.

**A3.4 `/3`.**

- All seven keys are required.
- `/1` and `/2` are refused with `unsupported schema version '<v>'`.
- These are refused with their C.14 lines:
  - a missing `counters` key gives `missing key 'counters'`;
  - an unknown counter table gives `counter table <t> is not in RECHECK_COUNTER_TABLES`;
  - a table listed twice gives `listed more than once` (this now covers `counters`).
