## Non-zero exits and failures

1. **02-unit-node22-unset.log, EXIT 1** (1 failed, 1586 passed of 1587; the second Vitest invocation therefore did not run): `apps/web/src/auth/session-identity.test.tsx > F-DG2-500 sign-out here and 403 (en) > signing out here clears everything…`, `findByText("No transformations yet")` timed out (Testing Library default 1000 ms) at line 295. The host load average was ~8 on 4 vCPUs (three reviewers running at once). The DOM dump shows user B's own home page ("Welcome, Synthetic User B") and the assertion just before it (line 293: A's secret is absent) passed, so no data of A leaked; the list simply had not rendered yet. The file is unchanged since DG2 (29da00d). Re-run: `02-unit-node22-unset-rerun.log` EXIT 0 (1587/1587 + 190/190), and `trials/02-session-identity-repeat-node22-unset.log`: 8 of 8 isolated repeats pass (18/18 each). Classified as a load-sensitive timing flake of a DG2 test, not a DG3 product defect; disclosed, not a finding.
2. **trials/01b-trial-1-wrong-formatter.log and trials/01c-trial-1-lint-step-wrong-formatter.log, EXIT 2 in the eslint steps**: my command used `--format unix`, which ESLint 10 no longer ships ("The unix formatter is no longer part of core ESLint"). Nothing was linted in those steps. Re-run with the default formatter: 01b/01c (below). The run-time steps of trial 1 gave the same results as 01c.
3. **01b-guard-static-negative-probe.log, EXIT 1 by design**: a throwaway `packages/shared/src/formula/zz-qa-probe.ts` with 15 forbidden forms (node:module/createRequire, node:inspector, a workspace import `@mth/shared`, `globalThis["ev"+"al"]`, `process.getBuiltinModule`, `Object.getPrototypeOf`, a `"constructor"` literal, a template key on a function expression, `self`, `import.meta`, a `Function` alias, `Reflect.construct`, `.constructor` read). ESLint refused every one (25 errors on lines 2–12 and 15–17). Lines 13, 14 and 18 only reference already-refused imports or a timer without calling it, and are not separate forms. The file was deleted; `git status` clean.
4. **01c-guard-runtime-mutation-probe.log, non-zero steps by design**: `index.ts` mutated to call the Function constructor through a key assembled at run time (`["con","struc","tor"].join("")` on `Math.max`). Static lint EXIT 0 (as ADR-0024 §6 states, a run-time key is outside any static rule); `vitest --project unit-node` on the formula dir EXIT 0 (184/184: invisible in a normal process); `vitest --project unit-formula-nocodegen` **EXIT 1, 25 failed / 165 passed, "EvalError: Code generation from strings disallowed for this context"**; `pnpm test` EXIT 1. Mixing `--project unit-formula-nocodegen --project unit-node` → startup error EXIT 1 (by design). Restored: `git status` clean and the no-codegen project EXIT 0 (190/190).
5. **trials/04-trial-1-unset-addStyleTag-csp.log, EXIT 1** (216 passed, 2 failed): F180b in chromium-en and chromium-ar threw `page.addStyleTag: Refused to apply inline style because it violates the following Content Security Policy directive: "style-src 'self'"` when setting up the 200% text state. That is the app's CSP working as intended; the error was in my probe. Fixed by setting the root font size through the CSSOM (`style.setProperty`) and writing the measurements after every page. Every other test of that run passed (same as the final runs).
6. **04-e2e-unset.log and 04-e2e-cutf8.log, EXIT 1 each: 216 passed, 2 failed.** The 2 failures are **F180b** in chromium-en and chromium-ar. The single failing assertion is spec line 1768 `expect(bad).toEqual([])`; the preceding assertions (77 measurements, other chips present, root font doubled 16→32 px) passed. In every project and setting, the 7 failing rows are exactly the 7 badges in **one state: 390 px viewport at 200% root text**. There, each badge lies **inside** its card/field (inside = true, no overlap, not clipped, wraps with `white-space: normal`), but the card itself is wider than the viewport. `.gate-list` is `repeat(auto-fill, minmax(18rem, 1fr))` (app.css:1506, unchanged since DG2 ea72d86), so at 32 px root text a card is at least 576 px, and the document scrolls horizontally (scrollWidth 633 > 390). The clause is therefore inside its card but partly to the right of the viewport, reachable by horizontal scrolling (`clauseInside` and `noHScroll` false). This state is about 195 CSS px of effective width, below WCAG 1.4.10's 320 px reflow requirement, and 1.4.4 (resize text) permits horizontal scrolling. It is a pre-existing property of the gate grid, not of the badge or F-DG3-180. Disclosed as an observation, not a finding. All 70 other measurements per project and setting (320–1920 px at 100%, and 1280 px at 200%) pass every criterion.
