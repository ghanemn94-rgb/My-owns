| D-018 | 2026-09-28 | delivery-orchestrator | **Findings integrity** (F-DG0-101, F-DG0-110). A finding can be closed (`CLOSED_VERIFIED` / `REJECTED_INVALID`) only by the **latest** entry for it in a reviewer-authored `<role>.verifications.json` sidecar. That entry must be PASS, by a reviewer who is not the owner, and bound to that reviewer's own post-freeze run for the round. `findings.json` must mirror it exactly. The fix revision must be a commit contained in both the verified round's candidate and the gate candidate, and the verification evidence must be existing repository files. Every review round recorded in `stages.json` must still exist, every round directory must be recorded, and no file under `reviews/<DGx>/` or `runs/<DGx>/` may ever be deleted from git history. Every finding raised in any review round (the reviewer sidecars under `reviews/<DGx>/round-N/`) must exist in `findings.json`. The fields the reviewer sets (stage, requirement, severity, mandatory flag, title, reporter) can't be altered there. Findings can't be relabelled to another stage. Only Low, non-mandatory findings can be accepted as observations, and that needs a specialist reviewer and the auditor. | This stops unresolved findings escaping a gate by being dropped, relabelled or downgraded. | — |

An agent can also end a turn with the first line `CLASSIFIER-BLOCKED` to request the same resume. The permission mode is unchanged. | Round 1 of DG0 lost the code-security reviewer's shell checks to this outage (its record was BLOCKED). | D-021 | 2026-09-28 | delivery-orchestrator | **Reviewer artefacts are bound to their run and are write-once** (F-DG0-115, F-DG0-208, F-DG0-117, F-DG0-102).<br>• **Run outputs.** The runner snapshots the tree before and after each run. It records in `meta.json` every file the run window changed (`outputs`, path → SHA-256) and the paths the agent wrote with its own file tools (`written_by_tools`). It auto-commits a reviewer's run directory together with its written files immediately.<br>• **Output binding.** The validator requires every gate review record, and every record and sidecar used to close or accept a finding, to equal what its run wrote.<br>• **Write-once history.** Committed files under `reviews/<DGx>/`, `runs/<DGx>/`, `candidates/<DGx>/` and `assignments/<DGx>/round-*/` may never be modified or deleted, whether in history or in the working tree.<br>• **Per-freeze manifests.** Each freeze writes its own write-once manifest `candidates/<DGx>/<id-prefix>.manifest.json`, and every review round's `candidate_id`, `frozen_at` and `source_commit` must match it.<br>• **Sidecar-only acceptance.** Observations are accepted only through bound sidecar entries (`status_after: ACCEPTED_OBSERVATION`) from a specialist reviewer and from the release-auditor. | Reviewer-written evidence can no longer be edited in place undetected. Closure and acceptance need artefacts produced by the reviewer's own run. Evidence from rounds 1–3 predates output recording, so every finding closure is re-confirmed in round 4 by bound runs. **Residual (disclosed):** run evidence is self-hashed rather than externally attested. A party able to fabricate a complete, internally consistent run directory *and* commit it as new history can still forge evidence. The remaining controls are the auditor's transcript review and the published git history. | An external attestation service becomes available, such as signed transcripts. |
