## The finding (F-DG1-127, Low, REQ-S16-003)
Two loader routes remain outside `LOADER_BUILTINS` after F-DG1-125:
- **A1 — `node:sqlite` native loader:** `import { DatabaseSync } from "node:sqlite"; new DatabaseSync(":memory:", { allowExtension: true }).loadExtension("/tmp/x.so")` loads a native shared object — the same class as the `process.dlopen` route F-DG1-125 closed — yet produces **0 violations**.
- **A2 — runtime code generation via `node:fs` + a same-module `import()`:** `import { writeFileSync } from "node:fs"; writeFileSync(new URL("./gen.mjs", import.meta.url), "…"); await import("./gen.mjs")` writes a file inside the module's own directory and imports it; the literal relative specifier passes the boundary check and the generated bytes are never seen by the lint — **0 violations**.
No module source uses `node:sqlite` or `node:fs` (only `apps/api/src/modules/admin/branding.test.ts` imports `node:fs`). Low/non-mandatory: a static defence-in-depth lint (ADR-0002) over code that is also human-reviewed and runs with a read-only production source tree, not a runtime security boundary.

## Required fix (the reviewer's recommendation; converge the class)
1. **Close A1 (the concrete native-loader route):** add `sqlite` to `LOADER_BUILTINS` (the existing `.flatMap(b => [b, \`node:${b}\`])` then bans both `sqlite` and `node:sqlite`). A module never needs SQLite — all persistence is through `@mth/db`/PostgreSQL (ADR-0003) — and a repo-wide grep finds zero imports, so there is no legitimate-use cost. This is consistent with the `process.dlopen` closure (F-DG1-125).
2. **Document the irreducible residual (A2 + the general class), do NOT ban `node:fs`** (a test imports it and a module may legitimately read files later; banning write-APIs-only is brittle). Extend the testkit header's existing "Residual limit" note (around lines 33–35) to state clearly, as the **accepted** residual of a *static* lint:
   - runtime code generation then dynamic import of a literal same-module path (write a file, then `import("./local.mjs")`) — the lint cannot see bytes produced at runtime; and
   - the loader/eval denylist is **enumerated** (rule 1 primitives + rule-3 roots + the `LOADER_BUILTINS` specifiers) and cannot be proven exhaustive over every host capability that could load or generate code at runtime (a future Node built-in, `WebAssembly` instantiation, …).
   State the rationale: this lint is static defence-in-depth for the ADR-0002 module boundaries, enforced against human-reviewed code running with a read-only production source tree — **not** a runtime security boundary; these residuals are accepted, not closable syntactically.
